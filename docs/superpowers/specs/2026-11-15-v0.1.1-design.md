0.1.1 fixes four small defects and one flaky test and changes nothing else. A user sees: a

only.

## 0. Decisions

### A. Ruled by the user (2026-11-15)

1. **#11: say so, do not open, do not refuse.** When a review's answer edits a plan with no
   visible editor, show an info notice `plan <name> changed · unsaved` with an `Open` action.
   The plan is not opened automatically and the edit is not refused.
2. **#14: cancel ask and validate on close; a running do keeps going.** Olifant runs ask and
   validate read-only; a do edits the working tree and is not killed mid-edit. Parts 2 and 3 of
   #14 (the proposal tab, the 0-line prompt) are recorded as already done by M7 (`fc44d89`); the
   issue closes with the PR.
3. **#20: nothing ships except one README sentence** on the limit on accepting only part of a
   plan ghost. The issue stays open.
4. **#23: fix `src/suggest/editor.ts:147-149`** (skip when `line >= lineCount`) and use
   `validatePosition` in `cursor()`; **add** the e2e guard suite that scans `exthost.log` (via
   `Api.logUri`) for "Illegal value" errors.
5. **The pause-test flake: fix the test only, no product change** (the page's load-time
   `sendSize` stays). Wait for a full-width `size` report, replace the `sleep(500)`s with a
   `sizes()` counter, fold in #10's `fake.12` `afterEach` cancel. Measure on 1.91.0 before and
   after. File the flake as an issue (at plan time or as the first task, §6).
6. **#22 and the other open issues are out of scope.**
7. **Out of scope:** bumping the olifant pin (M9, the next milestone) and Marketplace / Open VSX
   (deferred until after this release).

### B. Ruled by the spec (one reason each)

1. **One branch `v0.1.1`, one PR, version `0.1.1`, tag `v0.1.1`.** As M8 §0.A.2; the bump is part
   of the PR. The user tags after merge; the plan never tags (M8 §0.A.3).
2. **#14 cancels in `closed()`, not by keeping the entry alive.** Smallest change that stops the
   waste; keeping a do's entry so a reopened plan shows its pending mark and `Plan: Cancel`
   reaches it is a follow-up, not this patch.
3. **The #11 notice is said once per answer that touched the plan, only when `visibleTextEditors`
   has no editor of `planUri` at land time** (compared as `vscode.Uri.parse(planUri).toString()`,
   cf. #12's spelling note). Info level.
4. **#23 skips rather than clamps.** The selection event that follows every such shrink runs
   `moved` again with the fresh cursor; clamping would feed the controller a line the cursor is
   not on for one tick.
5. **The release is a bug-fix: no pre-tag manual checklist beyond an install smoke of the vsix,
   and no model-gated real e2e.** No server-facing change and no new surface (§5).

## 3. Design per item

### 3.1 #11: a push-opened review can edit a plan that is not open

Facts. `Reviews.ready(p)` (`src/pause/review.ts:66-70`) opens a review without checking that the
plan has an editor, by design ("the plan need not be open"). Olifant pushes `review/ready`
before the do answers (`Lsp.hs:1942-1946`), so the plan may have been closed while the do ran.
The answer lands through `answered` (`controller.ts:478-514`) and `landReview` (:518-531): the
edit through `applyServerEdit`, the facts through `openTextDocument(planUri)` +
`workspace.applyEdit`. Neither shows the document, and `applyEdit.ts:84-87` leaves an unopened
file open and unsaved (plans are skipped by the save loop, by design). The plan sits dirty in
`textDocuments` with no tab until the next open or the exit prompt. nvim does the same silently
(`review.lua:461-466`, `:168-183`).

Design. After `landReview` has applied an edit or facts to a plan and `visibleTextEditors` has
no editor of `planUri`, say once: `plan <name> changed · unsaved` (`<name>` = the plan's file
name), info level, with one action `Open` that runs `showTextDocument` on the plan. Nothing else
changes: the window still lands beside whatever is active (`panel.ts:14-15`), the plan is not
opened for the person, and the edit is never refused (the server has already kept or reverted
and dropped the review; refusing would desync the plan from it with no way back). When the plan
is visible, no notice.

Rejected: opening the plan on the push (`showTextDocument` with no column covers the file the
person is editing, `Beside` makes a third column; both intrude for a review they may answer with
one key) and refusing the edit.

Test. E2e, fake suite, `fake.13-review.e2e.ts`. Extend the push test (:53, "a do's review/ready
opens the do review without opening the plan"; its no-visible-editor assertion at :68 stays) or
add one: closeAllEditors, push `review/ready`, press `a` with a `planEdit`, assert `a.shown` has
the notice text and the plan document is dirty with no visible editor. A second test with the
plan visible asserts no notice. The `Open` click is a VS Code button and cannot be driven; the
e2e pins the text and the action name where `a.shown` exposes them, and the click goes to the
manual smoke (§4). No unit test.

Implementer: Sonnet (two files, well specified).

### 3.2 #14: closing a plan does not cancel the request

Facts. `closed(uri)` (`verbs.ts:357-366`, from `onDidCloseTextDocument`, :96) marks each entry
`gone` and drops it but does not call `e.cts.cancel()`; compare `cancel()` (:328-343), which does
both. The `gone` guard (:148, :153) already swallows a cancelled answer and its `-32800` word,
so a cancel on close says nothing. After `closed()` the entry is gone, so `Plan: Cancel` cannot
reach the request even if the plan is reopened, and the server runs it to the end. At the pin:
`$/cancelRequest` trips the job's token (`Lsp.hs:277-279`); a cancelled errand answers
`RequestCancelled` and is archived and journaled (`errandRequest`, `Lsp.hs:1918-1960`; `runErrand`);
`Errand.hs:69-83` `runnerArgs` runs ask and validate with `--allowedTools Read,Grep,Glob` (no
writes) and do with `--permission-mode acceptEdits`, `Edit`, `Write` and the test tools, editing
the working tree as it goes. nvim cancels nothing on `BufWipeout` (`plans.lua:1146-1148`).

Parts 2 and 3 of the issue are done by M7 (`fc44d89`): `src/plans/prompt.ts` was deleted, answers
wait as ghosts under their row and a close drops them (`verbs.ts:206-215`, :364-365); zero-line
blocks are held and drawn `ai · +0 lines` by design (`m7/m7-pr.md:14`; e2e `fake.15:417`). The
PR description says so and `Closes #14`.

Design. In `closed()`, for each entry with `e.verb !== 'do'`: `e.cts.cancel()` before `drop`. The
`gone` flag stays, so the cancelled answer says nothing. A do's entry is dropped as today, the
do runs to its end and its review is pushed; §3.1 then tells the person the plan changed. Cancelling
a do is unsafe: the runner dies mid-edit, its partial writes stay with no review to revert them
(a project without git has nothing to recover from). All three close routes fire `closed()`:
a clean document closes shortly after its last tab, a dirty one cannot close without a
save / don't-save decision, a language change closes and reopens (the existing test's route).

Test. E2e, `fake.15-verbs.e2e.ts`: (1) an ask with `reply('olifant/plans/ask', { hold: true, … })`
closed by language change as at :140 asserts `$/cancelRequest` with the ask's id was sent,
`running()` is empty, nothing shown, no `plans/outcome`; (2) a validate, the same; (3) a held do
closed the same way asserts no `$/cancelRequest` and nothing shown. The existing test at :140
changes from "nothing is sent" to "nothing but the cancel is sent". The `$/cancelRequest`
assertion pattern is `fake.15:100-122`. No unit test: `closed()` is VS Code event plumbing.

Implementer: Opus (cancellation ordering with `gone`, close-event timing and the do exception are
runtime-sensitive, though small).

### 3.4 #23: "Illegal value for `line`" from a text-change listener

Facts. The message comes from exactly one API, `TextDocument.lineAt` (`line < 0 || line >=
lineCount`; checked in the 1.91.0 extension-host bundle, stable 1.146.0 the same). Of the seven
`onDidChangeTextDocument` listeners only `src/suggest/editor.ts:125-128` → `moved(ed)` (:147-151)
calls `lineAt` with the selection line unguarded; the others only do row arithmetic or ranges,
clamp (`previewDoc.ts` `reveal`) or filter before `lineAt` (`rowMarks.ts:36`). The cause: VS Code
delivers the model change before the editor's selection update, so inside the listener
`ed.selection` is the pre-edit cursor, and an edit that shrinks the document past the cursor line
makes `lineAt(oldLine)` throw. The e2e does this in every suite's `after`/`afterEach`
(`fake.12:87-91`, main.py from 30 lines to `x = 1\n` with the cursor on line 3–20), which is why
it "fires in passing runs" with no save in flight (`m8/ci-first-run.md:102,124`); a user hits it
on any revert, reload or server edit that removes lines above the cursor. `cursor()`
(`editor.ts:56-61`) has the same pattern but runs from the debounce timer, when the selection is
fresh; harmless today. nvim keeps cursor and buffer consistent inside the autocmd; no race.

Design. In `moved`, `if (line >= ed.document.lineCount) return;` with a comment that VS Code
reports the model change before the selection. In `cursor()`, read the position through
`ed.document.validatePosition(ed.selection.active)` as insurance. No other behaviour change. (Not
possible: dropping the text-change listener; an edit on the cursor line that does not move the
cursor has no selection event.)

Test. The error shows only in the extension-host log, so the guard is a log scan.
- `Api.logUri` exposes `context.logUri`; its parent directory holds `exthost.log`.
- `fake.10-suggestions.e2e.ts`: open main.py (30 lines), cursor on line 25, `WorkspaceEdit`
  replacing all with 2 lines, assert the log gained no `Illegal value` line (log length read
  before and after). Before the fix this fails deterministically on both VS Code versions: the
  ordering is VS Code's, not timing.
- `fake.17-exthost.e2e.ts` (new; mocha runs files in name order, `test/e2e/index.ts`), the last
  fake suite: reads `exthost.log` and asserts no line matches
  `FAILED to handle event.*sorcererdev.durandal`. That guards every listener, not only this one.
The fix is verified red first: write both tests, watch them fail on `2241b48`'s code, then fix.

Implementer: Sonnet (a two-line fix; the log-scan harness is new but mechanical).

### 3.5 The pause-test flake (unfiled)

Facts. `fake.12-pause.e2e.ts:117-128` asserts at :124
`plain(a.pause.view()!.title).startsWith('conjure · CancelBooking.handle · ● paused')`.
`conjureAt` (:47-60) resolves when the tab exists (`windowTab`, `helpers.ts:70-76`), not when the
page has loaded. The controller starts at `cols = 120` (`controller.ts:62`); at load the page runs
`sendSize()` once, posts `size`, then `ready` (`webview/main.ts:121-138`); a `ResizeObserver`
re-measures with a 100 ms debounce; a `size` repaints at once (`controller.ts:159-161`). The
page's first measurement can be of an iframe not yet at its laid-out width, and has been seen to
report 28 and 46 cells (`fake.12:402`, `fake.13:65-67`, CI run 43622964717): `text` becomes 20 and
38 (`model.ts:412-417`, `:873-887`) and the title is cut (`conjure · CancelBoo…`), so :124 fails.
Whether :124 runs before, during or after that transient depends on page load time against the
test's 100 ms polling; local 1.91.0 hits it often, CI and stable mostly not. In the product it is
a cut title for under 200 ms that nobody sees. `cols` also persists across windows (never reset on
`hide()`). The suite already dodged it twice (:379-380, `fake.13:65`) and sleeps 500 ms before its
own size at :402-405 and :467-469.

Design (test only; the page's load-time `sendSize` stays).
1. `PauseApi.sizes()` returns the count of `size` messages `controller.receive` has seen.
2. In the test at :117, after `conjureAt`, wait for the page's first report
   (`until(() => a.pause.sizes() > before)`), then send the test's own full-width size
   (`await a.pause.receive({ type: 'size', cols: 200 })`) and assert the title at once. `receive`
   → `paint` is synchronous and the continuation of an awaited resolved promise is a microtask; a
   page message is a macrotask and cannot interleave, so the view read is the one at 200 cols.
3. The two `sleep(500)` waits (:404, :468) become the same `sizes()` wait, then the test's own
   `size` as today.
4. `afterEach` cancels a run left in the air by a failing test: `a.tdd.cancel()` when
   `a.pause.view()?.state === 'running'` (#10's second test item; bounds the blast radius of any
   future failure in the suite).

Rejected: asserting `state` and `tab` instead of the title (loses the title check); dropping the
page's load-time `sendSize` (product change for a test, reduces but does not remove the
transient); an uncut `titleFull` in `View` (more API for one assertion).

Test. The fix is the test. Measure: `VSCODE_VERSION=1.91.0 DURANDAL_E2E_ONLY=fake.12 npm run
test:e2e`, three runs before (expect at least one :124 failure) and three after (expect none),
each in the foreground under a timeout. The numbers go in the PR description.

Implementer: Opus (the change is small; the verification is a race measurement across two VS Code
versions).
